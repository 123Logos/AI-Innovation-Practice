# MVP 范围说明书（Phase 1）

> 本文件是 Phase 1 的唯一范围依据。与 Word 产品文档冲突时，以本文件为准。
> 修改本文件需两人共同确认，并记录在文末“变更记录”。

## 1. 一句话定义

让一名 AI 专业在校生，在手机或电脑上完成“登录 → 填写技能与项目经历 → 生成一页 A4 简历 → 预览编辑 → 保存”，并愿意把结果拿去投实习。

## 2. 目标用户（Phase 1 只服务这一群人）

- 核心：大二、大三 AI 专业，有实习意向、但简历还没写或写不好 的学生。
- 次要：负责推荐实习的任课老师（Phase 1 只作为旁观验收者，不做教师端功能）。

## 3. 用户主路径（必须完整跑通）

1. 学生用邮箱/用户名注册并登录；
2. 填写：姓名、专业、年级、联系方式、3–8 项技能（含自评等级）、1–3 段项目/实践经历（标题、时间、描述、个人职责）；
3. 点击“生成简历”，系统在 10 秒内返回一页 A4 简历预览；
4. 学生可在线编辑文字、调整模块顺序、重新生成；
5. 保存后可在“我的简历”中再次打开、编辑、导出 PDF。

## 4. 功能清单（Phase 1 只做这些）

| 编号 | 功能 | 必须 | 说明 |
|---|---|---|---|
| F1 | 注册 / 登录 / 登出 | 是 | 邮箱或用户名 + 密码，密码哈希存储 |
| F2 | 学生档案 CRUD | 是 | 姓名、专业、年级、联系方式 |
| F3 | 技能 CRUD + 自评等级 | 是 | 等级 1–5，Phase 1 允许自评（题库测评属冻结项） |
| F4 | 项目/实践经历 CRUD | 是 | 标题、起止时间、描述、个人职责 |
| F5 | 生成简历 | 是 | 允许模板或极简 prompt；输出 HTML，可导出 PDF |
| F6 | 简历预览与在线编辑 | 是 | 文字可改、模块可排序 |
| F7 | 简历保存与再次打开 | 是 | 持久化到 `resumes` 表 |
| F8 | 一页 A4 约束 | 是 | 默认不超过 1 页，最多 1.5 页；超出时提示精简 |
| F9 | 响应式布局 | 是 | 375px 与 1280px 下主路径可用 |
| F10 | 统一错误提示 | 是 | 表单校验失败、生成失败均有可读提示 |

## 5. 冻结清单（Phase 1 一行实现代码都不写）

- 模拟面试（文字/电话/视频/WebRTC）
- 人岗匹配、自动推荐、批量简历下载
- AI 爬虫采集岗位、企业需求自动解析
- 标准化题库测评、AI 用户画像
- 行业标杆人物库
- 教师端学情看板、学校课程反哺报告
- 真实 DeepSeek 或任何真实外部 AI 调用
- Redis、ARQ、Celery、S3、消息队列、后台任务框架
- 小程序 / 原生 App

冻结项只允许以文档、接口占位、`# PHASE-2: not wired` 形式存在。

## 6. 数据范围（Phase 1 只建 5 张表）

`users`、`student_profiles`、`skills`、`experiences`、`resumes`

- 只通过 Alembic 迁移创建，每个迁移必须有 downgrade；
- 设计草案见 `docs/design/schema-draft.sql`（**非迁移源**）；
- 新增表必须走 ADR。

## 7. 非功能要求（Phase 1 最低线）

- 手机与电脑主路径可用；
- 单次简历生成 ≤ 10 秒（stub 阶段应 ≤ 2 秒）；
- 密码不得明文存储；
- 关键配置缺失时启动失败；
- 所有 API 错误响应格式统一；
- 至少 1 个集成测试覆盖 F1–F7 主链路。

## 8. 验收标准（Definition of Done）

Phase 1 完成 = 同时满足：

- [ ] 一名真实学生能在手机上独立完成主路径，无需开发者口头指导；
- [ ] 同一学生能在电脑上完成同一路径；
- [ ] 生成结果不超过 1 页 A4（最多 1.5 页），字段完整；
- [ ] 保存后重新打开，内容不丢失；
- [ ] 集成测试覆盖主链路，CI 全绿；
- [ ] `alembic upgrade head` 与 `downgrade base` 均可跑通；
- [ ] 至少 5 名真实用户使用记录（姓名 + 截图/录屏 + 一句反馈 + 一个卡点）；
- [ ] 未触碰冻结清单。

## 9. 明确不做的事（防止范围蔓延）

- 不追求“AI 写出文采好的简历”，只追求“整洁、规范、字段完整、可编辑”；
- 不做多套简历模板市场，Phase 1 只做 1 套模板；
- 不做社交、评论、点赞、积分；
- 不做管理后台，数据修正由开发者直接操作数据库；
- 不做多语言。

## 10. 交付物映射（对应 Word 文档提交要求）

| Word 要求 | Phase 1 如何满足 |
|---|---|
| 精益画布 | 用真实用户反馈迭代 v1→v2，保留版本 |
| 技术总结报告 | 以 ADR-001/002 + 迁移/CI 决策为骨架撰写 |
| 测试报告 | 每个切片完成后填轻量表，不最后补 |
| 10 个真实用户 | Phase 1 先完成 5 个，Phase 2 补齐 10 个 |
| 宣传视频 | 用真实操作录屏剪辑，不用演示稿 |
| PPT 答辩 | 用真实用户记录 + 测试输出作为核心素材 |
