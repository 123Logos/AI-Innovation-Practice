# AI赋能职业发展和面试指导平台

## 1. 文档说明

- **版本**：1.0
- **产品形态**：响应式 Web 应用，电脑与手机浏览器均可使用
- **目标**：连接学生、教师、企业/校友和学校管理者，把“岗位需求—能力评估—成长行动—求职结果”形成闭环
- **本阶段范围**：完整产品规格与验收口径；具体代码按《开发与架构文档》实施

## 2. 产品定位

平台面向人工智能及相关专业高校，提供岗位洞察、能力画像、人岗匹配、简历生成、模拟面试和教学决策支持。产品不替代教师、职业指导老师或企业面试官，而是提供可解释的证据、建议和练习环境。

### 2.1 核心价值

| 用户 | 核心价值 |
|---|---|
| 学生 | 知道目标岗位要求，知道自己的差距，并获得可执行的成长任务 |
| 教师 | 了解班级学情和行业变化，能进行更精准的指导 |
| 企业/校友 | 提交岗位需求，获得符合条件且可解释的候选人清单 |
| 学校管理者 | 获得专业建设、课程调整和就业质量的聚合数据 |

## 3. 用户角色与权限

1. **学生**：维护个人资料、技能证据、项目、目标岗位；参加测评和面试；管理简历与授权。
2. **教师**：查看授权范围内的班级聚合数据，指导学生，审核岗位和推荐结果。
3. **企业/校友**：提交和维护岗位，查看获得授权的候选人摘要，发起沟通。
4. **学校管理员**：管理院系、班级、角色、数据权限和平台配置，查看脱敏统计。
5. **平台管理员**：处理内容审核、模型配置、审计和故障，不得默认查看学生私密原文。

权限原则：默认拒绝、最小权限、按学校/院系/班级隔离；个人简历、面试音视频和测评原文必须有明确授权才能被他人查看。

## 4. 典型用户故事

- 作为大一学生，我希望选择一个目标岗位，看到技能差距和每周行动任务，而不是等到毕业才开始准备。
- 作为大三学生，我希望用项目证据生成一页简历，并知道每条经历如何对应岗位要求。
- 作为教师，我希望看到班级技能缺口的趋势，而不是读取学生不必要的私密对话。
- 作为企业，我希望提交岗位后得到带匹配理由和证据的新鲜候选人，而不是无法解释的分数。
- 作为学校管理者，我希望比较岗位需求与课程覆盖情况，为专业建设提供数据依据。

## 5. 产品范围与版本

### 5.1 MVP（首期必须交付）

1. 注册、登录、学校/班级归属和角色权限。
2. 学生档案、技能、项目、证书和求职目标。
3. 企业岗位录入、审核、技能拆解和岗位状态管理。
4. 标准化技能测评、自评与项目证据采集。
5. 可解释的人岗匹配和能力差距清单。
6. AI 简历草稿生成、在线编辑、PDF 导出和版本管理。
7. 文本模拟面试；预留语音/视频实时会话适配层。
8. 教师班级看板和企业候选人推荐下载。
9. 审计日志、授权记录、AI 任务状态与失败重试。

### 5.2 第二阶段

- WebRTC 语音/视频模拟面试和面试复盘。
- 岗位变化雷达、行业技能热度和薪资区间。
- 成长任务打卡、项目里程碑和证据链评分。
- 企业反馈回流、推荐结果质量评估。
- 教师批注、学生成长报告和课程缺口分析。

### 5.3 暂不纳入

- 不承诺自动作出录用、淘汰、升学或学业处分决定。
- 不将 AI 评分作为唯一招聘依据。
- 不在平台内保存银行卡、身份证完整照片等非必要高敏感资料。
- 不在前端直接调用 DeepSeek 或暴露任何模型密钥。

## 6. 核心业务流程

### 6.1 学生成长闭环

注册/加入学校 → 完善目标岗位 → 测评与提交项目证据 → 生成能力画像 → 选择目标岗位 → 查看差距 → 接收成长任务 → 任务完成并补充证据 → 更新匹配度 → 生成定制简历 → 模拟面试 → 复盘改进。

### 6.2 企业岗位闭环

提交岗位 → 字段校验与内容审核 → AI 提取技能/经验/通用能力 → 教师或管理员确认 → 发布 → 生成候选人 → 企业查看授权摘要 → 沟通/反馈 → 结果统计。

### 6.3 教师教学闭环

选择班级和时间范围 → 查看聚合能力缺口 → 对比目标岗位趋势 → 查看经授权的学生详情 → 发布指导任务 → 观察完成率和变化 → 输出班级/课程建议。

## 7. 功能需求

### FR-01 账户与组织

- 支持邮箱/手机号登录，生产环境使用 JWT；支持刷新令牌和主动注销。
- 学校管理员可维护院系、班级和成员邀请。
- 账号必须绑定组织；跨组织数据不可见。
- 登录、改密、角色变更和管理员操作写入审计日志。

### FR-02 学生档案与能力证据

- 档案包括教育经历、期望城市、目标岗位、项目、实习、证书、作品链接和技能。
- 技能包含熟练度、最近使用时间、来源（自评/测评/项目/教师确认）和证据。
- 任何 AI 推断必须标记为“建议”，学生可修订或拒绝。
- 学生可导出、撤回授权和申请删除个人数据。

### FR-03 岗位管理与分析

- 岗位包含企业、地点、薪资区间、工作方式、职责、硬技能、软技能、经验和截止时间。
- AI 分析输出必须使用结构化 JSON，并保存模型、提示词版本、时间和置信度。
- 未经审核的岗位不可进入推荐池；过期岗位自动下架。
- 岗位来源可为人工录入、学校导入或合法授权的数据接口；不默认抓取受限制的网站。

### FR-04 测评与画像

- 题目按技能、通用能力和情景任务分类，支持版本化。
- 评分由规则评分、测试结果和人工/AI 评语组成；保留原始答案。
- 能力画像展示“已验证、待验证、待提升”三种状态，避免把自评当成事实。

### FR-05 人岗匹配

匹配分数仅用于排序和解释，默认由以下因素加权：

`总分 = 0.45 技能覆盖 + 0.20 证据强度 + 0.15 经验相关度 + 0.10 目标偏好 + 0.10 时效/可用性`

权重由管理员配置并记录版本。结果必须展示：

- 已满足要求及其证据；
- 部分满足项；
- 缺口、建议行动和预计验证方式；
- 分数版本、更新时间和数据新鲜度。

### FR-06 简历

- AI 根据已确认资料生成一页优先、最多 1.5 页的简历草稿。
- 不得虚构项目、指标、学历、证书或工作经历；缺少信息时输出待补充标记。
- 支持模板、区块编辑、版本对比、PDF 导出和针对岗位的定制版本。
- 导出前显示隐私检查：联系方式、作品链接、个人信息和授权范围。

### FR-07 模拟面试

- 按岗位、简历和面试轮次生成问题，覆盖专业深度、项目追问、行为问题和反问环节。
- 支持文本 MVP；接口预留 WebRTC 房间、音视频流、转写和评分适配器。
- 每轮结束生成证据化反馈：回答相关性、结构性、具体性、技术深度和表达建议。
- AI 不得提供保证录用的结论；敏感问题和歧视性评价需拦截。

### FR-08 推荐与教师看板

- 教师可按岗位、技能、年级、班级和授权状态筛选候选人。
- 批量下载只包含获授权字段，并记录下载人、范围、时间和用途。
- 看板默认聚合到班级/专业，人数过少时隐藏可识别明细。

## 8. 创新点（在原设想上增加）

1. **证据链能力图谱**：把技能连接到项目提交、代码仓库、测评答案、教师确认和面试表现；同一技能可查看证据新鲜度，减少只看自评分。
2. **岗位变化雷达**：对已审核岗位按时间聚合技能频次、变化趋势和新兴技能，给出“课程/成长任务建议”，不提供未经验证的薪资承诺。
3. **可解释匹配卡**：每个匹配结果都能展开“为什么匹配、还差什么、如何验证”，支持学生对结果提出纠错。
4. **成长任务自动编排**：把差距转化为 7/14/30 天的可执行任务，任务完成必须上传成果或反思，形成闭环。
5. **AI 结果双轨制**：模型输出与人工确认分离，保存原始建议、修改记录和最终版本，可回溯、可撤销、可评估。
6. **隐私控制中心**：学生按字段和场景授权（教师指导、企业推荐、公开简历、面试复盘），支持过期授权、撤回和访问记录。
7. **课程-岗位覆盖矩阵**：学校端对比岗位高频能力与课程/实践覆盖，输出“新增课程、实践项目、竞赛方向”的证据清单。

## 9. 非功能需求

- 可用性：核心读接口 P95 < 500 ms；AI 任务采用异步状态，不阻塞主请求。
- 安全：HTTPS、密码哈希、短时访问令牌、刷新令牌轮换、SQL 参数化、上传校验、审计和限流。
- 隐私：数据最小化、目的限定、授权可撤回、脱敏导出和生命周期删除。
- 可靠性：AI/媒体供应商不可用时，业务数据可正常访问；任务可重试且幂等。
- 可维护性：后端分层、类型约束、OpenAPI、数据库迁移、自动化测试和结构化日志。
- 可访问性：键盘操作、清晰焦点、颜色不作为唯一信息载体，移动端断点适配。

## 10. 核心指标与验收

### 10.1 产品指标

- 注册后完成档案率、目标岗位设置率、测评完成率。
- 岗位分析成功率、匹配结果查看率、成长任务完成率。
- 简历导出率、模拟面试完成率、面试后再次练习率。
- 推荐查看率、企业反馈率、教师看板周活。

### 10.2 验收标准

1. 新用户可在 10 分钟内完成注册、目标岗位和第一份能力档案。
2. 岗位分析可展示结构化技能和置信度，失败时有可见状态和重试入口。
3. 简历不产生未经用户确认的事实；PDF 在桌面和手机预览中布局稳定。
4. 匹配结果至少展示三条可验证证据或明确缺口。
5. 未授权用户无法读取学生私密简历、面试记录和音视频。
6. DeepSeek Key 不出现在浏览器网络请求、日志、错误栈和仓库中。
7. 关键操作均可在审计日志中定位操作者、对象、时间和结果。
8. 真实用户试用需取得同意并记录匿名化反馈，不伪造使用数据。

## 11. AI 治理与研究依据

本产品将招聘/职业推荐视为高影响辅助场景，采用 NIST AI RMF 的 Govern、Map、Measure、Manage 闭环：明确责任人，登记风险，持续测量，按严重度处理。AI 只提供建议和排序，不自动作出录用、淘汰、学业或处分决定；必须保留人工复核、申诉和纠错通道。

### 11.1 可验证生成

- 岗位分析、简历和面试反馈优先从已授权的档案、岗位和证据中检索，生成结果逐条绑定来源 ID。
- 将生成内容拆成原子事实，记录 `supported/unsupported/needs_review` 状态；存在未支持事实时不得直接标记为“已确认”。
- 每次 AI 输出保存模型、提示词版本、输入数据版本、来源、置信度、人工修改和最终采纳状态。
- 岗位变化雷达只使用已审核且带时间戳的数据，并展示样本数和时间范围，避免把小样本趋势当成结论。

### 11.2 公平、申诉和人工监督

- 匹配和推荐不得使用性别、民族、年龄、健康、宗教等敏感属性，也不得使用其明显代理变量作为排序依据。
- 在脱敏且满足最小样本门槛的前提下，按群体检查选择率、误差率和结果差异；低样本只报告“不足以评估”，不展示个人推断。
- 学生可以查看影响结果的岗位要求、证据和缺口，提交纠错；教师/管理员可冻结结果并重新审核。
- 企业查看的是经授权的候选人摘要，不获得未经同意的测评原文、面试音视频或私密对话。

### 11.3 依据

- [NIST AI RMF 1.0](https://doi.org/10.6028/NIST.AI.100-1)：可信 AI 的可靠性、安全、公平、隐私、可解释、透明、问责和韧性。
- [NIST Generative AI Profile](https://doi.org/10.6028/NIST.AI.600-1)：生成式 AI 的专门风险管理建议。
- [EU AI Act Regulation (EU) 2024/1689](https://eur-lex.europa.eu/eli/reg/2024/1689/oj)：就业和招聘 AI 场景的高风险治理参考；本项目采用人工监督、日志、数据治理和透明告知作为设计基线，不宣称因此自动满足法律合规。
- Gao 等，[Retrieval-Augmented Generation for Large Language Models: A Survey](https://arxiv.org/abs/2312.10997)：检索、生成、增强三部分和可追溯知识更新思路。
- Min 等，[FActScore](https://arxiv.org/abs/2305.14251)：将长文本拆成原子事实并计算可靠来源支持比例；本项目将其转化为事实支持率测试。

## 12. 风险与应对

| 风险 | 应对 |
|---|---|
| AI 幻觉或虚构简历内容 | 只允许从已确认数据生成；事实引用和人工确认；敏感输出拦截 |
| 匹配歧视或错误淘汰 | 只做辅助排序；公开因素和版本；提供纠错和人工复核 |
| 学生隐私泄露 | 字段级授权、组织隔离、脱敏、审计、最小化保存 |
| 岗位数据过期 | 到期下架、显示更新时间、定期复核 |
| 群体差异或代理偏见 | 特征白名单、群体指标、人工复核、申诉和版本回滚 |
| 生成内容无证据 | 检索来源绑定、原子事实检查、未支持内容人工确认 |
| 模型或媒体服务中断 | 异步任务、重试、超时、供应商适配器和降级提示 |
| 学生低频使用 | 目标岗位引导、成长任务、阶段反馈和教师辅导闭环 |
