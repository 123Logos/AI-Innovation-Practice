# ADR-018：润色字数从「硬截断」改为「目标 + 超限标注」

- 日期：2026-11-09
- 状态：**已生效（决策已定，实现属批次 F6，且其后端那半与批次 B4/B8 同批，见 `docs/ROADMAP.md` §1 与 §3；本 ADR 不含代码）**
- 决策人：人类负责人。原话（2026-11-09 第一轮回复第 1 点）：**「润色上限改成『不砍尾 + 标注超出 N 字，让用户自己减』」**
- 关联：ADR-009（BYOK 非流式，`ai` 失败绝不静默降级）、ADR-010（润色与生成解耦）、`docs/FRONTEND_DESIGN.md` C4 / C5 / S5、`docs/API.md` §6

## 1. 背景：老板报的「输出不全，被硬限制死了」，砍它的是我们

润色链路上一共只有这几处能限制字数，取证如下（数字全部读自代码）：

| 环节 | 约束 | 出处 |
|---|---|---|
| 输入 | 每段 `description`/`responsibility` ≤ 2000 | `app/schemas/resume.py:123-124` |
| 用户设定的目标 | `max_words`，`ge=40, le=800`，缺省补 **200**，且**只对 `expand` 档有意义** | `app/schemas/resume.py:139/142-152`、`:98 DEFAULT_MAX_WORDS` |
| 发给模型的话术 | expand：「严格不超过 {max_words} 个汉字」；heavy：description ≤120 汉字、responsibility ≤60 | `app/integrations/copy_writer.py:76/80/85/90` |
| **模型调用的 token 预算** | **没有**：请求体只有 `model/stream/messages/thinking`，**不含 `max_tokens`**，本路径也没有 `finish_reason == "length"` 处理 | `copy_writer.py:178-189`（对比 `evidence_scorer.py:265`、`skill_extractor.py:108`、`match_service.py:90/423` 才有） |
| 响应契约 | `PolishedExperience.description ≤ 600`、`responsibility ≤ 300`；不合格 → **整单 502** | `resume.py:165-166`、`copy_writer.py:217` |
| **服务端砍尾** | `_cap_pair`/`_cap_text`：把 description+responsibility **合计**压到 `max_words` 以内，按句末 `rfind` 断句后 **`window.rstrip()` 直接丢尾** | `app/services/resume_service.py:112-113/125/129-138/141-159` |

**结论：这一条链路上不存在"被 API 的 token 切断"。** 让用户看到半句话的，是我们自己的 `_cap_text`，而且它**不留任何痕迹**——没有省略号、没有 `truncated` 标记、响应体（`ResumeCopy`，`app/schemas/resume.py:169-178`）里根本没有能表达「被砍过」的字段，所以前端连想说都无从说起。这正面违反老板 2026-11-04 的裁定（`ADR-009:24`「AI 失败时绝不静默降级」）与守则 C4。

还有一件必须写在决策之前的实事：**今天 600/300 这条响应契约从来没被撞到过，仅仅是因为 `_cap_pair` 先把文字砍进了它以内。** 一旦按老板的要求不砍尾，这条契约第一次变成可达路径——合法输入（`max_words=800`，模型写 700 字描述）会直接把整个请求打成 502。所以「放宽响应契约」不是可选优化，**它是本决策的前置条件**，两件事必须同一个 PR。

## 2. 决策

1. **`max_words` 从「命令」降级为「目标」**：`expand` 档**不再按 `max_words` 砍尾**，`_cap_pair` 从这条路径上移除。用户设的字数控不住模型的笔，只控得住提示词里的请求语气——这一点不再假装。
2. **超限变成可见信息，不变成损失**：`PolishedExperience` 增加两个字段（新增，非破坏）：
   - `target_words: int | None`——本次请求对它生效的目标（`expand` 才有，其它档 `None`）；
   - `over_limit_by: int`——实际字数超出目标多少，不超则 `0`。
   命名与语义对齐既有的 `MatchMeta.truncated` / `fragments_truncated` 词汇表，**不新造一套说法**。
3. **响应契约随之前置放宽**：`description` `600 → 1200`、`responsibility` `300 → 600`。取这个数只为一句判据：`max_words` 的上限是 800（description+responsibility 合计），放宽后单字段必然容得下合法输出，不再需要第二条硬边。
4. **模型写飞了怎么办（超出放宽后的契约）**：**不再整单 502**。该段标记 `truncated=true` 并截到契约上限，其余段照常返回，前端把这一段说清楚（守则 C4）。这条把「一次坏输出毁掉整次润色」换成了「坏的那段坏，好的那段能用」，同时仍然可见——两端都不许静默。
5. **界面怎么办（老板 2026-11-09 同一条回复的第 2 点已经定调）**：接受润色后**立刻**把新文字填进左侧表单，同时把「生成简历」升为主操作高亮态并给一行轻量提示（「内容已更新，点击生成最新简历」）；**不许自动重生成**——那是替用户花他的额度。超限提示挂在对应段落旁，措辞遵守 C3：给动作（「删掉 N 字再保存」），不许只说「超出」。

## 3. 后果

- **两条测试要跟着改写，而且是裁定不是拆护栏**：`tests/test_resume_ai_copywriting.py:360 test_expand_caps_oversized_model_output` 与 `:380 test_expand_caps_at_sentence_boundary` 现在锁的是「超了就砍」，本 ADR 之后锁的是「超了就标注」。改的是断言的**方向**，不是把测试删掉——新断言必须同时验 `over_limit_by` 的数值正确（不是只验字段存在）。
- `tests/test_resume_ai_copywriting.py:402 other_modes_keep_model_text_untouched` 与 `:323/:333`（prompt 注入 `max_words`）、`:729`（40–800 区间）**不动**：提示词仍然带目标字数，其它档仍然不碰文字。
- **API 变更是加字段，不是改语义**，所以不算破坏性变更；`docs/API.md` §6 要加这两个字段的读法，并加一句「超出目标是标注而不是截断」。
- 额度影响：不砍尾意味着模型偶尔会写更多字，BYOK 下**这部分由用户承担**，而用户已经知道自己设过上限——这是他的选择，不是我们的浪费。但 `max_words` 作为提示词约束仍然留着，它仍然是成本闸。
- 一处真实取舍必须写明：**放宽响应契约后，简历里可能出现比用户预期更长的段落**，而一页 A4 是硬约束（`MVP_SCOPE.md:35`）。这不靠截断解决，靠批次 F6 的那条链路解决——超限时用户减字 → 再点生成；生成侧若仍超页，走 ADR-015 §3 那条「超长时要不要截断/缩字号」的可见文案决定，而不是回头偷偷砍。

## 4. 替代方案

- **(a) 提高 `max_words` 上限或把默认 200 调大**：仍是同一个病，只是把刀磨钝——超限照样静默丢尾。
- **(b) 保留截断，只加一个省略号**：用户看到「…」却不知道少了多少、也无处可查，属于把静默降级说得稍微好听一点，违反老板 2026-11-07「不静默降级是掩耳盗铃」的原话精神。
- **(c) 加 `max_tokens` 让 API 来切断**：把不可见的切断从我们手里换到上游手里，还要处理 `finish_reason == "length"` 的半句话；而且它同样无法告诉用户少了多少。
- **(d) 超目标就整段拒收**：用户的额度已经花了，结果一段都不给，比现状更糟。

## 5. 落地批次

落在 **批次 F6**（批次编号的唯一来源是 `docs/ROADMAP.md`；2026-11-09 之前写的是「`docs/FRONTEND_DESIGN.md` §10 那张表」，那个权威已移交，违例明细仍留在守则 §10）：前端 = `applyPolish` 补失效 + 点亮主行动 + 超限提示 + save 走内容差异；后端 = 删砍尾、加 `target_words`/`over_limit_by`、放宽响应契约、超契约改段级标注、PUT 的 no-op 检测。**其中 no-op PUT 必须与 `ADR-015` 的「全量替换 + 软删除」同批或更早**，否则每次无变更保存都在给子表盖 `deleted_at` 并复制一份历史行。

## 6. 补记（2026-11-09 第 5 轮）：硬边界不删，但每次咬人必须留痕

老板原话：**「ADR-018 硬边界仍要存在但要可见」**。这一条**不改变 §2 的五个决策**，它做的是把一种误读钉死——「`max_words` 从命令降级成目标」**不等于**「取消字数上限」。三道边界一道都不撤，只是每道的职责被写清：

| 边界 | 数值 | 它现在管什么 | 它不再管什么 | 咬到人时用户看到什么 |
|---|---|---|---|---|
| 输入侧 schema | `max_words` `ge=40, le=800`（`app/schemas/resume.py:139`） | 拦住离谱请求，仍是 422 硬校验 | 不再被当成「输出必须这么长」的承诺 | 422 的文案要说「这个上限是 40–800」并给动作（守则 C3），不许只回「请求参数校验失败。」 |
| 响应侧契约 | `description ≤ 1200`、`responsibility ≤ 600`（§2.3 放宽后） | 最后一道硬边：模型写飞时截到契约上限，**段级**而不是整单 | 不再靠 `_cap_pair` 提前砍进它以内来假装不可达 | 那一段 `truncated=true`，界面把**这一段**指出来并说「模型写得比上限还长，已被截断」。**不承诺报出少了多少字**（老板 2026-11-09 第 6 轮：「维持『出现但标注』，不改」）——我上一版在这里加过一条「要给出截断前的实际长度」的实现要求，**被他否掉，此处按否决结论改写**，理由记在 §6 末 |
| 版式侧 | 一页 A4（`docs/MVP_SCOPE.md:35` 的「F8 一页 A4 约束」） | 生成结果的长度上限 | 不许反过来用截字凑页 | 超页时的「缩字号还是减字」是 §3 末留的那格未决问题，属可见文案决定，仍待拍 |

**机械判据（实现时怎么算违反本 ADR）**：任何一次减损都必须能在响应体里回答两件事——**哪一段、这是自动的还是用户自己选的**；能报数的那一道还要报数。按边界分层，别把两道的要求混成一道：

| 触发的是哪道边 | 必须可见的东西 | 「少了多少」的口径 |
|---|---|---|
| 超**目标**（`max_words`，未撞契约） | `target_words` + `over_limit_by` + 段落定位 | **必须有数**：`len(返回文字) − target_words`，用户据此自己减字（§2.5 的那句「删掉 N 字再保存」） |
| 超**契约**（1200/600，最后一道） | `truncated=true` + 段落定位 + 一句人话说明 | **不要求有数**（本条按老板 2026-11-09 第 6 轮定案，见下） |

前端把 `over_limit_by` / `truncated` 任一标记吞掉（不显示，或只在控制台打日志）同样算违反：「可见」的定义是**在用户已经看着的那块区域里可见**，不是「响应里有这个字段」。

**被否掉的一条（我当时认为它是逻辑必然，老板不这么判，理由记在这儿）**：我上一版要求契约级截断额外返回**截断前的实际长度**，好让「少了多少」在两道边上都成立。他的裁定是「**维持『出现但标注』，不改**」——契约那一道的义务到「出现 + 标注」为止。这跟 `ADR-009:24`「绝不静默降级」不冲突：静默的反面是**说出来**，不是把损失量化到字。**How to apply**：批次 F6 实现时不许顺手加 `truncated_from_words` 之类字段；`MatchMeta` 那套 `truncated` / `fragments_truncated` 词汇表保持现状，响应体加字段属于 §4.6 事件，得先有理由再来问。
