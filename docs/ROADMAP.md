## 0. 编号规则（先把名字定死，否则这份文件自己就是第四个名字）

`F` 这个前缀在本仓库里**同时是三种东西**。取证：

| 写法 | 指什么 | 定义在哪 |
|---|---|---|
| `MVP_SCOPE.md` §4 的 F1–F7 | **功能**编号（F1 注册/登录 … F7 简历保存） | `docs/MVP_SCOPE.md:28-34` |
| 守则 §5 的 F1–F3 | **条款**编号（守则 F1 = 多行输入高度自适应） | `docs/FRONTEND_DESIGN.md` §5 |
| 本文件的 F1–F7 | **批次**编号 | 本文件 §1 |

**读法（自本文件起，写文档、写 PR、写 commit 都按这个来）：**

- 批次：必须写成「**批次 F3**」。上下文是「谁先做 / 谁挡谁 / 多大」时说的才是批次。
- 条款：必须带章节，写「**守则 F1**」「守则 §5 F1」。
- 功能：必须带出处，写「**MVP_SCOPE §4 F5**」。
- `E:\我要做什么.txt` 里那份 1–10 是他给我的**需求清单**，不是第四套批次号，不许进任何文档引用（它只出现在本文件 §1 那张表的「对应他清单第几条」列里，到此为止）。

我认真考虑过把前端批次换成 `FE1…FE7` 彻底避开——**没换**：他自己最新一句就叫它「F 编号」，词汇以用户已经用出来的为准，改名比留一条读法规则更贵（守则 §10 那张表已随 PR #15 进了 master，改名要连带动 4 份 ADR）。要换，一个字的事，见 §6 第 3 条。

## 6c. 文档代码引用机制（第 11 轮拍定：(b) + (c)，不选 (a)）

闸在 `scripts/check_docs_citations.py`（v2），CI 步骤不变。四条判据，全都能红：

| 判据 | 写法 | 红了意味着什么 |
|---|---|---|
| 老三条 | `` `path:12-34` `` | 文件没了 / 行号越界 / 区间首末行是空行 |
| **符号存在性**（新） | `` `path::symbol` `` | 那个符号在被引文件里**没有定义**——文档在指一个不存在的东西 |
| **锚点不漂**（新） | `` `path:12-34` 的 `foo()` `` | `foo` 的定义不在这个区间里；报错直接给出「它在第 N 行」 |
| **易变文件不留行号**（新） | `` VOLATILE_PATHS 里的 path:12-34 `` | 必须改写成 `path::symbol`；名单在脚本里显式维护 |

三条边界，避免这条闸变成看着绿的空检：

- **易变性不从 git 历史算**。CI 是浅克隆（`actions/checkout` 默认 depth=1），任何依赖 `git log` 的判据在那儿会**恒真**。所以名单显式写在脚本常量里，维护规则也写在旁边：某文件被第二批改动且 `docs/` 引用了它，就把它加进来。
- **锚点判据只在「该符号在这个文件里确有定义」时生效**。文档点名的若是 CSS 类名、SQL 片段、枚举字面量，判据不插手——否则闸会因为合法文案变红，那种闸最后只能被注掉。
- **今天锚点判据扫到 0 处**，这是实况不是笔误：可锚的那一条（`API.md` 的 `requirement_match()`）随本批改成了符号式。它是**前瞻闸**，我用临时探针文件证明过它真会红（`锚点漂移：app/api/v1/jobs.py:60-90 说它是 match_job()，而 match_job 的定义在第 198 行`），探针文件已删。

本批已按 (b) 改写完 25 处（`ADR-007` 3、`ADR-013` 8、`ADR-015` 3、`ADR-016` 1、`ADR-017` 2、`API.md` 7、`FRONTEND_DESIGN.md` 1）：能定位到所属符号的写成 `path::symbol`，行号指向纯注释块的退成文件级引用（不硬造符号）。闸顺带抓出两条**本来就写错的符号名**：`auth.ts::applyToken` 实为 `applySession`、`student_profile_repository.py::replace_profile` 实为 `replace_profile_content`。

现状计数：显式路径行号式 270 条 + 符号式 76 条 + **裸文件名式 38 条**（这一层 v1 完全看不见，而守则的证据列恰恰这么写），问题 0 处。

补裸文件名是必须的，否则「少写一个目录」就是绕过 (b)+(c) 的旁路。这一层顺带抓出一条 v1 永远看不见的真错：`ResumeEditorView.vue` 的一个行号指向 127，而那个文件只有 123 行。易变名单对裸文件名同样生效，本轮按 (b) 去掉 69 处行号（9 个文档）。**我没有自动补符号**——试过，答案是错的：自动定位把 `AppTopBar.vue` 那对旧行号（265-284）判给了 `goTrash`，因为那几行现在住着 `goTrash`，而文档说的是那份手写监听。行号上「最近的定义」不等于文档在说的那件事，这正是脚本 docstring 一开始就写明的「机械平移保证不了语义」。所以语义不明的只剩文件级引用，它只是不再宣称精确，不会把文档改成假事实。
