## 1. 文案（C = Copy）

| 编号 | 规则 | 怎么算违反（判据） | 今天的状态 |
|---|---|---|---|
| **C1** | 用户可见文本**严禁 emoji**，包括用作图标的 ASCII 符号（`✨ 💡 ✓ ✗ ★ ⚠ ← ↑ ↓ ↺ ✦`）。要图标就用 SVG/字体图标，且 `aria-hidden="true"` + 相邻有文字标签。 | 一条正则扫描模板与字符串常量（§9 G1），命中即红。 | **违例 6 处**：`StylePanel.vue:339/350/354`、`AppTopBar.vue`、`JobCreateView.vue:264/380`；伪图标另计（`←` 5 个返回链接、`↑↓` 排序、`↺`）。 |
| **C2** | **严禁开发者黑话**上屏：服务商名、`Key`/`token`/`API`/`JSON`/`JWT`、`提示词`/`模型`/`非流式`/`上游`/`额度`/`后端在跑`、状态码数字。必须说人话时，说「谁来用这把尺子/花的是你的用量」这类**用户视角的因果**。唯一豁免：用户必须亲手去某个界面拿凭据时，可以出现那个界面里的原词（如他自己在「AI 设置」里粘贴的字段名）。 | 违例词表 + 扫描（§9 G1），豁免用行内标记。 | **违例密集**：`AppTopBar.vue:329/604/615/621`（DeepSeek API Key、`sk-……`、`<code>deepseek-flash</code>`、非流式）、`stores/job.ts:545/547/549/599/603/613`、`JobCreateView.vue`、`PolishSettingsDialog.vue:100`、`api/client.ts:333`。 |
| **C3** | 每一句失败提示必须**要么给出用户修得动的下一步，要么明说没有下一步**。「请求参数校验失败。」「请稍后重试。」这类无主语无动作的句子不许单独出现。 | 每个错误分支的文案常量必须命中「动作动词表」或「无可为表」之一（§9 G3）；今天的做法是人读。 | 违例：`app/main.py:212`（422 → 「请求参数校验失败。」）、`app/api/v1/jobs.py:62-65`（502 直显「被服务端的 token 上限切断了」）。 |
| **C4** | **绝不静默降级、绝不静默截断**。系统替用户做了任何减损（截尾、回落模板、跳过某段、少处理几条），必须在同屏说出来，并说清是自动的还是他选的。依据是老板 2026-11-04/11-08 两次原话（`ADR-009:24`、`ADR-013:381`）。 | 任何返回被减损的响应必须带一个可见标记位；前端不许把它吞掉。 | **已裁定（2026-11-09 第一轮，`ADR-018`）**：润色不再砍尾，改为「目标字数 + 超出多少字」的可见标注，减字动作交回用户。当前代码仍在砍（`app/services/resume_service.py::_cap_text`），且 `tests/test_resume_ai_copywriting.py:360/380` 把砍尾钉成契约——**这两条测试随 ADR-018 的实现一起改写，属裁定落地，不是我把护栏拆了**。 |
| **C5** | 界面不解释技术构成：权重、归一分母、计数、版本号一律不上屏；但**「用户修得动的失败原因」必须分句保留、不许合并**（`ADR-013:608-610/784-785`，`stores/job.ts:558-569`）。 | 新增解释性文案要回答「这句话能不能变成用户的动作」；`weight_sum_used`/`*_version`/`candidate_pairs` 出现在模板即红。 | 合规（有注释 + `stores/job.ts:579` 裁定）。 |
| **C6** | 同一类产品状态**只允许一套机制**：提示只走一个 toast/内联反馈组件，确认只走一个自绘弹层。**禁用 `window.confirm` / `window.alert`**。 | ESLint `no-restricted-globals`（§9 G2）。 | **违例 6 处已清零**（批次 F1b，PR #21，2026-11-10）：`AppTopBar.vue` 三处（删除档案 / 去回收站前的未保存拦截 / 保存失败的 alert）、`StylePanel.vue`（生成前）、`stores/resume.ts`（切换前——这一处没有模板可渲染，所以弹窗状态必须全局）、`RecycleBinView.vue`（彻底删除）全部改走同一个 `stores/dialog.ts` + `components/ConfirmDialog.vue`，形态照 `JobDetailView.vue` 的先例。**同一产品两种做法**这一格从此收口。 |

## 3. 动效与加载（M）

| 编号 | 规则 | 判据 | 现状 |
|---|---|---|---|
| **M1** | 内容区的进入/退出**不许硬切闪现**：统一「淡入淡出 + 微位移」，位移 ≤ 8px，时长与缓动**必须取自令牌**，不许写死数字。 | 模板里出现裸 `transition:`/`animation:` 字面量即红；只能用 `var(--motion-*)`。 | **今天 0 个 `<Transition>`、0 个 `@keyframes`**，全站只有 3 处硬编码过渡（`AppTopBar.vue:752/763` 的 `.15s ease`、`StylePanel.vue` `.12s`）。令牌层还没有——**M1 必须先补令牌再补动效**，否则就是把硬编码从 3 处变成 30 处。 |
| **M2** | 异步内容必须**先占位后填充**：骨架屏（或等高的占位块）+ 固定最小高度托底，尺寸取该区块稳定态的实测值，不许凭感觉写 `min-height`。 | 每个「加载后才出现内容」的容器必须有 `min-height` 令牌或骨架组件；jsdom 测不了视觉，但结构可测。 | 违例面很大：**无骨架、无 spinner**，7 处只有文字提示（`ResumeEditorView.vue`、`JobBoardView.vue`、`JobDetailView.vue` 等）；`aria-busy` 只挂在 2 个按钮（`JobCreateView.vue`、`JobDetailView.vue`）。 |
| **M3** | **动效不许掩盖状态不确定**：加载中、失败、空态三种必须各自可读；`prefers-reduced-motion` 下降级为无位移（可保留淡入）。 | 媒体查询存在且被 skeleton/transition 共用一个开关。 | 未实现（全仓 0 处 `prefers-reduced-motion`）。 |
| **M4** | 页面内不许出现「动画驱动的功能」：任何数据正确性判断不许等动画结束再执行。 | 逻辑里不许出现 `setTimeout(…)` 与过渡时长耦合。 | 现状未见耦合（`DRAFT_WRITE_DELAY=400ms` 是本地草稿写入节流，属 debounce 不是动效）。 |

## 4. 布局与导航（L）

| 编号 | 规则 | 判据 | 现状 |
|---|---|---|---|
| **L1** | **一个布局，一处定义**。`app-shell` + 顶栏这类外框不许在每个视图里复制；由路由的嵌套布局承担。 | 视图里出现第二处 `<AppTopBar />` 手工摆放即红（今天 7 处：`ResumeEditorView.vue`、`JobBoardView.vue`、`JobCreateView.vue`、`JobDetailView.vue`、`RecycleBinView.vue`、`JobTrashView.vue` …）。 | **✅ 已收口（批次 F2，PR #24）**：外框与顶栏只在 `components/AppLayout.vue` 一处，6 个视图各自的 `app-shell` 与 `<AppTopBar />` 已删。`git diff -w` 复核过：每个视图的真实改动恰好是那 6 行，diff 里其余两千多行全是缩进。左边那 6 个视图行号锚点随本批失效，本列不再维护它们。 |

## 5. 表单与长文本（F）

## 6. 状态与数据（S）

| 编号 | 规则 | 判据 | 现状 |

| **S1** | **一个状态只有一个真源**。同一件事不许既有 draft 又有一份生成快照还互不知情：改了 A 就必须显式处置 B（作废或重算）。 | 每个写 store 的函数必须显式调用失效函数；出现「A 类操作会 invalidate、B 类不会」就是缺陷。 | **已有一处违反老板报告的症状**：`updateTheme`/`moveSection` 会 `invalidateGeneratedResult(...)`（`stores/resume.ts:920/950/979`），而 `applyPolish`（`:1612-1638`）**不调**——于是接受润色后，纸面仍显示上一次生成的 HTML 快照（`ResumePreview.vue` 的 `v-html="generatedBody"`，来源 `resume.ts`，那是**后端按库里的行**渲染的，`resume_service.py`）。这正是「接受修改后左边部分没有立即同步内容（应该也有后端部分）」：前后端都有份，前端缺失效、后端确需重生成。 |

| **S3** | 服务端对「没变化的 PUT」也不许留下副作用假象：`updated_at` 不许无谓 bump，子表不许无谓重建。现实现是每次 PUT 全删重插并换全新 UUID（`student_profile_repository.py:483-526`），而 `rename_profile` **已经做过 no-op 检测**（`profile_service.py:187-194`，测试 `test_profiles.py:1150-1163`）——先例在，照它做。⚠️ 与 `ADR-015` 冲突点：一旦子表改「全量替换 + 软删除」，无变更的 PUT 会**每次都盖一遍 `deleted_at` 并复制一份历史行**，等于把脏写放大成历史爆炸。**所以 S3 必须与 B4/B8 迁移同批或更早落地。** | 一条集成测试：同体 PUT 两次，`updated_at` 与子表 id 集合必须不变。 | 违例（今天第二次 PUT 会重建子表，且 `test_profiles.py:294` 正把「重建」钉成契约，改动是裁定不是修复）。 |
| **S4** | 401 出口唯一（`frontend/src/router/index.ts:170-177`），任何请求层不许自己跳登录页或弹第二套提示。 | 401 处理只允许出现在那一处。 | 合规。 |
| **S5** | **失效即点亮主行动，不许偷偷重算**。当用户的操作让「已生成的东西」过期（接受润色、改主题、改排版、改文案），界面必须：① 立刻把新内容写进它该在的地方（表单），② 把主行动（「生成简历」）升到高亮主操作态，③ 在其旁边给一行轻量提示说明为什么要点它。**不许自动调用**——那会替用户花他自己的用量（老板 2026-11-09 原话：「让用户自己决定什么时候点『生成』。这样既不会偷偷消耗额度，也做到了『高等级功能醒目』」）。 | 任何让生成物失效的 store 动作必须调用同一失效函数并点亮同一个主行动；出现「A 类操作会 invalidate、B 类不会」即缺陷。 | **今天正是那个缺陷**：`updateTheme`/`moveSection` 调 `invalidateGeneratedResult(...)`（`stores/resume.ts:920/950/979`），`applyPolish`（`:1612-1638`）不调，也没有「点亮主行动 + 一行提示」这一层。归**批次 F6** 修，同时它也是 V1 在失效态下的具体形态。 |
